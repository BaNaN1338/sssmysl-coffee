# Смысл — сайт кофейни

Сайт меню и предзаказа с админкой, интеграцией с кассой YTimes и Android-обёрткой.

## Структура

- `index.html` — только разметка страницы.
- `site.css` — стили.
- `app.js` — клиентский код.
- `privacy.html`, `terms.html` — политика конфиденциальности и условия заказа.
- `build.mjs` — проверка сборки.
- `smoke.spec.js` — браузерные smoke-тесты.
- `.github/workflows` — CI, синхронизация меню и резервные копии.
- `supabase/functions/*` — исходники Edge Functions (также задеплоены в Supabase).
- `supabase/sql` — SQL-миграции.

## Локальный запуск

```bash
npm install
npm run build
npm start
```

Сайт будет доступен на `http://127.0.0.1:8080`.

## Проверки

```bash
npm run build
npm test
```

CI запускается на каждый push в `main` и на pull request.

## Деплой

Сайт публикуется через GitHub Pages из ветки `main`. После изменения `app.js` или `site.css` выполните `npm run build` и закоммитьте файлы.

## Секреты Supabase Edge Functions

- `YTIMES_API_KEY` — ключ интеграции YTimes.
- `YTIMES_SHOP_GUID` — GUID точки «Рождественская».
- `YTIMES_WEBHOOK_SECRET` — секрет для вебхука статуса заказа.
- `YTIMES_SHOP_GUID_GORKOGO` — опционально, если появится вторая точка.

## Секреты GitHub Actions

- `SUPABASE_SERVICE_ROLE_KEY` — для синхронизации меню по расписанию и резервных копий. Не публиковать.
- `BACKUP_PASSPHRASE` — пароль шифрования резервных копий.

Без этих секретов workflows синхронизации и бэкапа просто пропускаются.

## Синхронизация с YTimes

Функция `sync-ytimes-menu`:

- получает меню и стоп-лист YTimes;
- обновляет цены в `site_settings.config.drinks[].volumeOptions`;
- выставляет `stopped` и `stoppedVolumes`;
- обновляет `menuSyncedAt`;
- доступна из админки кнопкой «Синхронизировать с YTimes»;
- запускается по расписанию каждые 15 минут через GitHub Actions.

Новые позиции меню автоматически не добавляются: для них нужен маппинг в `site_settings.config.ytimesMap`.

## Статусы заказов

Функция `order-status`:

- отдаёт гостю статус заказа по `orderGuid`;
- принимает вебхук YTimes `ACCEPTED` / `CANCELLED` по секретному URL;
- после вебхука отправляет мгновенное обновление в Supabase Realtime (канал `order:<guid>`).

На сайте:

- окно заказа подписано на Realtime-канал и обновляется сразу;
- раз в 30 секунд остаётся резервный опрос на случай сбоя Realtime;
- GUID последнего заказа хранится в `localStorage` 2 часа, поэтому окно и статус восстанавливаются после перезагрузки страницы;
- статус видит только автор заказа; общей ленты заказов нет.

В админке на вкладке «Заказы» владелец видит последние 50 заказов: номер, гостя, телефон, сумму, статус, комментарий и состав. Список обновляется каждые 20 секунд. Доступ закрыт RLS: гость не может прочитать таблицу `orders`.

Вебхук нужно вставить в YTimes:

**Настройки → Интеграции → Сайт+Приложение → Webhook API → Статус заказа, созданного по API.**

Готовый URL лежит в `C:\Users\art52\OneDrive\Рабочий стол\SmyslAndroid\ytimes-webhook.txt`.

Для этой функции проверка JWT в Supabase должна быть **выключена**, иначе YTimes не сможет отправить вебхук.

Ограничение: гость видит статус, пока страница открыта. Для push/SMS/Telegram нужна отдельная интеграция.

## Юридические документы

`privacy.html` и `terms.html` — шаблоны. Перед публикацией замените:

- `[ИП/ООО «Смысл»]`
- `[ИНН]`
- `[ОГРН/ОГРНИП]`
- `[адрес]`
- `[email]`
- `[телефон]`

Согласие на обработку персональных данных обязательно отмечается в корзине перед отправкой заказа.

## Мониторинг

Ошибки клиента пишутся в таблицу `public.client_errors` (Supabase). Читать их может администратор с `app_metadata.role = "admin"`.

## Резервные копии

Workflow `backup.yml` раз в сутки выгружает `site_settings` и `orders`, шифрует архив паролем и хранит его 30 дней как GitHub Actions artifact.

## Ограничения

- Одна точка YTimes.
- Нет онлайн-оплаты.
- Нет мультиарендности.
- Новые позиции меню требуют маппинга.
- Уведомления о статусе — только на открытой странице.
