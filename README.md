# Смысл — сайт кофейни

Сайт меню и предзаказа с админкой, интеграцией с кассой YTimes и Android-обёрткой.

## Структура

- `index.html` — только разметка страницы.
- `site.css` — стили.
- `app.js` — клиентский код.
- `privacy.html`, `terms.html` — политика конфиденциальности и условия заказа.
- `build.mjs` — проверка сборки.
- `smoke.spec.js` — браузерные smoke-тесты.
- `.github/workflows` — CI, синхронизация меню и резервные копии.
- `supabase/functions/*` — исходники Edge Functions (также задеплоены в Supabase).
- `supabase/sql` — SQL-миграции.

## Локальный запуск

```bash
npm install
npm run build
npm start
```

Сайт будет доступен на `http://127.0.0.1:8080`.

## Проверки

```bash
npm run build
npm test
```

CI запускается на каждый push в `main` и на pull request.

## Деплой

Сайт публикуется через GitHub Pages из ветки `main`. После изменения `app.js` или `site.css` выполните `npm run build` и закоммитьте файлы.

## Секреты Supabase Edge Functions

- `YTIMES_API_KEY` — ключ интеграции YTimes.
- `YTIMES_SHOP_GUID` — GUID точки «Рождественская».
- `YTIMES_WEBHOOK_SECRET` — секрет для вебхука статуса заказа.
- `YTIMES_SHOP_GUID_GORKOGO` — опционально, если появится вторая точка.
- `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` — ключи web-push для push-уведомлений.
- `SYNC_CRON_SECRET` — секрет для вызова синхронизации из Supabase Cron.

## Секреты GitHub Actions

- `SUPABASE_SERVICE_ROLE_KEY` — для синхронизации меню по расписанию и резервных копий. Не публиковать.
- `BACKUP_PASSPHRASE` — пароль шифрования резервных копий.

Без этих секретов workflows синхронизации и бэкапа просто пропускаются.

## Синхронизация с YTimes

Функция `sync-ytimes-menu`:

- получает меню и стоп-лист YTimes;
- обновляет цены объёмов в `site_settings.config.drinks[].volumeOptions`;
- автоматически добавляет новые напитки из YTimes;
- поддерживает точные названия объёмов («350 мл горячий» / «350 мл холодный»);
- выставляет `stopped` и `stoppedVolumes`;
- обновляет `menuSyncedAt`;
- доступна из админки кнопкой «Синхронизировать с YTimes»;
- запускается каждые 15 минут через **Supabase Cron** (pg_cron + pg_net);
- GitHub Actions остаётся резервным запуском раз в 6 часов и для ручного запуска.

Новые позиции добавляются автоматически, кроме еды, добавок, мерча и служебных групп. Позиция получает id `yt-<guid>`, категорию по группе YTimes и цены/объёмы из YTimes.

Если новая позиция не нужна на сайте:

1. Удалите её в админке.
2. Её GUID попадёт в `config.ytimesIgnored` и синхронизация не будет добавлять её снова.
3. Кнопка «Вернуть скрытые» очищает список и возвращает позиции.

Старые сезонные группы «Летнее меню» и «ВЕСНА 2026» уже добавлены в `ytimesIgnored`, чтобы не засорять меню в ноябре. При необходимости их можно вернуть.

## Статусы заказов

Функция `order-status`:

- отдаёт гостю статус заказа по `orderGuid`;
- принимает вебхук YTimes `ACCEPTED` / `CANCELLED` по секретному URL;
- после вебхука отправляет мгновенное обновление в Supabase Realtime (канал `order:<guid>`).

На сайте:

- окно заказа подписано на Realtime-канал и обновляется сразу;
- раз в 30 секунд остаётся резервный опрос на случай сбоя Realtime;
- GUID последнего заказа хранится в `localStorage` 2 часа, поэтому окно и статус восстанавливаются после перезагрузки страницы;
- статус видит только автор заказа; общей ленты заказов нет.

В админке на вкладке «Заказы» владелец видит последние 50 заказов: номер, гостя, телефон, сумму, статус, комментарий и состав. Список обновляется каждые 20 секунд. Доступ закрыт RLS: гость не может прочитать таблицу `orders`.

### Чек и комментарий YTimes

В YTimes передаётся короткий комментарий, который печатается на предчеке/чеке:

- номер заказа;
- состав заказа;
- время приготовления;
- комментарий гостя.

Имя, телефон и итог в комментарий не дублируются — они хранятся в `orders` (номер — в колонке `order_number`) и видны в админке. В карточке заказа YTimes гость и телефон передаются отдельно через `client`, поэтому кассир видит их в заказе. Номер заказа печатается на чеке, а имя/телефон/итог — нет.

Вебхук нужно вставить в YTimes:

**Настройки → Интеграции → Сайт+Приложение → Webhook API → Статус заказа, созданного по API.**

Готовый URL лежит в `C:\Users\art52\OneDrive\Рабочий стол\SmyslAndroid\ytimes-webhook.txt`.

Для этой функции проверка JWT в Supabase должна быть **выключена**, иначе YTimes не сможет отправить вебхук.

Без push гость видит статус, пока страница открыта. С включёнными push-уведомлениями статус приходит, даже если вкладка закрыта (браузер должен быть запущен).

## Push-уведомления

- В окне заказа есть кнопка «Уведомить, когда заказ примут».
- Гость разрешает уведомления, браузер создаёт подписку, она сохраняется в `public.push_subscriptions` и привязывается к GUID заказа.
- После вебхука YTimes функция `order-status` отправляет push через `web-push` и VAPID-ключи.
- `sw.js` показывает уведомление, если вкладка не активна. Клик открывает сайт, окно заказа восстанавливается из `localStorage`.
- Если страница открыта, её уже обновляет Realtime, поэтому системное уведомление не дублируется.
- Для диагностики у `push-subscribe` есть действие `action: "test"` (только с JWT администратора).

Ограничения:

- браузер должен быть запущен (в фоне или на экране);
- на iPhone нужна установка сайта на экран «Домой», iOS 16.4+;
- если уведомления запрещены в настройках браузера, кнопка покажет «Уведомления запрещены в браузере»;
- push не заменяет SMS/Telegram и не работает, если браузер полностью закрыт.

## Юридические документы

`privacy.html` и `terms.html` — шаблоны. Перед публикацией замените:

- `[ИП/ООО «Смысл»]`
- `[ИНН]`
- `[ОГРН/ОГРНИП]`
- `[адрес]`
- `[email]`
- `[телефон]`

Согласие на обработку персональных данных обязательно отмечается в корзине перед отправкой заказа.

## Мониторинг

Ошибки клиента пишутся в таблицу `public.client_errors` (Supabase). Читать их может администратор с `app_metadata.role = "admin"`.

## Резервные копии

Workflow `backup.yml` раз в сутки выгружает `site_settings` и `orders`, шифрует архив паролем и хранит его 30 дней как GitHub Actions artifact.

После шифрования workflow проверяет восстановление: расшифровывает архив, сравнивает список файлов, проверяет наличие меню и заказов и печатает `restore OK`. Это защищает от ситуации, когда бэкап создаётся, но не расшифровывается.

## Ограничения

- Одна точка YTimes.
- Нет онлайн-оплаты.
- Нет мультиарендности.
- Еда, добавки и мерч из YTimes автоматически не добавляются — только напитки.
- Push-уведомления работают, пока браузер запущен; на iPhone — только для установленного PWA.
- Юридические реквизиты в `privacy.html` и `terms.html` пока заменены плейсхолдерами.
